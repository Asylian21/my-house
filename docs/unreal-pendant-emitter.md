# Source pendant emissive candidate

This adopted candidate targets only `DOM_01375`, **LIVING-103-DINING · centrálne závesné svietidlo · 2700 K difúzor**. It creates a versioned opaque DefaultLit material under `/Game/Brezi/MaterialStudies/PendantEmitter/V_<recipe SHA>` and enables that component's `emissive_light_source` through `SetEmissiveLightSource`. It adds no light actor. The source geometry, collision, UVs, Nanite settings, source material asset and the other 28 components using `MAT_0046` remain unchanged. The cord `DOM_01373` and shade `DOM_01374` are protected too.

The importer and candidate scripts are adopted. Native imports 4 and 5 both exited successfully, activated the material and passed both saved-map checks and the package input gate. The repeat import also validated replacement of the already active pendant. Evidence is preserved under [pendant-native-proof](../output/unreal/pendant-native-proof/). All 97 eligible Nanite meshes report the explicit normal fallback policy; the pendant retains all 2,704 source triangles and has 2,600 rebuilt render-LOD triangles. The clean-lens macOS build cooked and packaged successfully in `output/unreal/clean-lens-navigation-package-1.log` (UAT exit 0, 126.55 seconds). Its first 3840 × 2160 night image is preserved in `output/unreal/manual-ui-20260908-v7/`; the wide default bloom halo is removed by an ArchitectureCamera BloomIntensity=0 override. This is an idealized clean-lens choice, with unchanged emitter power and exposure. The bright globe remains clipped. Settled day terrace/pool/street views and the night room were visually inspected; temporal lighting quality is not yet accepted. Native entrypoints refuse execution outside their canonical path. `import_scene.py` preflights the source before map replacement, applies this stage after furniture oak and before final collision/asset hashing, and incorporates its pipeline and asset hashes into the final import receipt. There is no runtime dependency on an ignored study JSON: the recipe is recomputed from the normal pinned export scene and OBJ.

The 200 mm globe has 2,704 source triangles, including 104 zero-area pole triangles. Its 2,600 outward faces form a closed surface after a 0.00001 mm positional weld. The measured polygonal area is **0.125281846030128 m²**, about 0.304% below the analytic sphere area. Native bounds, identity transform, slot and collision are checked independently. The native source MeshDescription is read through scalar triangle-corner, vertex-instance and position getters. All 2,704 triangles must match canonical vertex positions, connectivity, multiplicity and winding after the Unreal cm/handedness conversion. Matching uses the existing 0.00001 mm source weld, a maximum 0.002 mm per-coordinate float-bridge tolerance and an absolute area tolerance of 0.00000025 m². Ambiguous nearby vertices fail rather than being assigned arbitrarily.

The read-only native source probe measured **0.125282012952539 m²**, an area difference of 0.000000166922411 m², and maximum vertex displacement of **0.001522071 mm**. All 1,302 unique source positions and all faces matched. This validates the imported source, not the normal render fallback surface area or a dedicated ray-tracing proxy. The source photometric recipe remains unchanged; it is not normalized to a coarse fallback.

The first native preflight also exposed a real fallback-policy defect: the importer stored percent=1 and relativeError=0 while leaving `fallback_target=Auto`. UE5.8's builder substitutes its Auto error, so that mesh had only 256 render-LOD triangles despite retaining the complete source. The existing importer Nanite branch now explicitly selects `PercentTriangles`, retains percent=1/error=0 and verifies/records the actual getters after its reflected property update. This intentionally rebuilds normal fallback data and changes generated asset bytes; canonical source geometry and material recipes remain unchanged. It is not a byte-preservation claim across that rebuild. Dedicated ray-tracing proxy selection/topology remains a separate, unverified runtime policy.

Only full-import pre-deletion permits a legacy Auto source pendant, after exact source proof and only with no active ownership state, no component override, the exact source material and a false emitter flag. Active or untracked state fails. Newly authored and active pendant validation requires the explicit full fallback policy and rebuilt render topology of 2,600 triangles, or all 2,704 if the zero-area poles remain. It never accepts 256 as full-detail geometry. Saved/reloaded source proofs must agree. Asset hashes and before/after component snapshots separately prove the subsequent material-only stage did not change the imported mesh.

**800 intrinsic lumens is an authored assumption, not a manufacturer specification.** With constant outward Lambertian emission, `Phi = pi * surfaceArea * luminance`, yielding **2,032.600229 cd/m²**. The source's 2700 K label is converted using the UE5.8 `FLinearColor::MakeFromColorTemperature` polynomial and normalized to Y=1 with explicit BT.709 weights `(0.2126, 0.7152, 0.0722)`. Linear emissive RGB is approximately **(3930.237916, 1634.668958, 386.653871)**. No channel clamp, sRGB encoding, repeated warm tint or manual pre-exposure multiplier is applied. The same power remains on during day and night.

The importer reads `RendererSettings.WorkingColorSpaceChoice` and all four chromaticity coordinates and rejects anything except initialized sRGB/BT.709 with D65. It records the legacy-luminance setting but uses the declared weights explicitly. This validates settings, not the render-thread working-space uniform. The typed `BreziRendererSettingsAudit` C++ bridge reads the CDO integer and coordinates because this UE5.8 build does not export `RendererSettings` or its enum to Python. Its header and implementation are pinned in the material recipe. Two read-only NullRHI probes confirmed the exact CDO identity and initialized Rec.709/D65 coordinates; only Python enum conversion failed. In this uncooked editor build, `CanEverRenderOrProduceRenderData` is true even under NullRHI, so no rendering flag or settings mutation is required. An uninitialized, foreign or non-BT.709 result still fails; the bridge returns invalid outside the editor or off the game thread.

Base color, roughness, metallic and specular are read from the original glTF material instance's named parameters. They must match the pinned source recipe (including `SpecularFactor=0`); those native values are retained. The new graph has exactly five constants and five verified output links. It is opaque, DefaultLit and single-sided on the verified outward surface. The original glTF double-sided setting is deliberately replaced at component level so inward faces do not create another emitting side. There are no textures, time nodes, custom shaders, normal changes, WPO, opacity or ray-dependent branches.

UE's hidden PixelDepthOffset enum is checked through the typed editor bridge's
actual expression-input getter, not the cached material summary. The native
graph check and package gate require that output to remain disconnected. Earlier
Python enum failures are preserved separately; they occurred before activation.

The existing shade is a **closed, capped** source frustum and intersects the upper part of the globe. Earlier deterministic source-only ray quadrature estimated roughly **289 lm escaping the shade** from the assumed 800 intrinsic lm; this excludes room transport, shade interreflection and transmission and is not a measured fixture output or a confidence interval. Do not rescale the source power to force 800 lm into the room. See the [source audit](../output/unreal/interior-fixture-lighting-study/emissive-alternative.md).

Apply saves the new material and reloads the map before activation, then applies the exact override and emitter flag, saves/reloads again, and checks native graph constants, output nodes/channels, ownership metadata, the flag and unchanged protected state/assets. These are two **map** reloads; they do not claim two explicit material-package garbage collections. Prior override arrays (including empty/null slots) and the prior emitter flag are retained. A failed activation restores both, restores metadata and requires a successful saved-map readback. A preactivation failure reports preservation separately from rollback; a failed map reload attempts to restore the original saved map without saving the blank map. `restore_pendant_emitter` performs the same complete ownership preflight before reversing the state and rolls back to the active candidate if reversal verification fails.

Full reimport has two explicit metadata transitions. Before any generated actor is deleted, the existing oak preflight and the pendant preflight both pass. The pendant checks the exact source mesh, source slot, transform, bounds, collision/GI flags and either the untouched source binding or its owned active graph, recipe, single override and emitter flag. A foreign or stale active binding fails; it is not accepted as recovery. Immediately before deleting the validated pendant actor, only `BreziPendantOriginalState` and `BreziPendantRevision` are removed. Unrelated metadata is read back unchanged, and a failed deletion restores the exact prior presence and values, including empty values.

UE5.8 metadata is keyed by actor path, so an independently reused historical path can inherit values even after live-actor cleanup. After Interchange returns its newly created actors and `configure_and_measure` validates the complete source geometry, the existing shared creation initializer proves freshness, mesh identity, source coverage and empty source override arrays for the whole new canonical set before any metadata mutation. The pendant-enabled importer explicitly selects the closed set of **six** keys: the existing four TV/furniture oak keys plus the exact pendant pair. Only those keys on newly created canonical actors are cleared, with actor paths, affected source IDs, removed keys and unrelated-metadata readback recorded. Manual/pre-existing actors, unrelated keys and package-wide orphan entries are untouched. A meshless hierarchy actor carrying any selected key is rejected. The helper's default remains oak-only; mismatched caller/plan scopes and every arbitrary, partial or duplicated scope are rejected. The old oak active-ownership guard remains unchanged.

The standalone pendant authoring/restoration guard remains strict. Reimport initialization is available only at the full importer's source-validated creation boundary. There is no ongoing failed-state exception or broad metadata purge. Changing an already-active pendant recipe requires a reviewed migration rather than treating the old material as compatible automatically.
