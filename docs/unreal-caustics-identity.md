# Diagnostic receiver identity policy

The Metal capture keeps its original source object and triangle indices. A diagnostic comparator now reports exact object matches, explicitly listed float32 ambiguities and unexplained mismatches separately. It does not merge architectural identities, assign a common material or BRDF, deposit nonfloor power into the floor atlas, or add production lighting.

The reviewed source contract is pinned to SHA-256 `c7c8011b3d7623e8780c30ea77775472a0cab7ebefa0f5cb97528f96580d404a`. The policy bytes are independently pinned in `Tools/identity_policy.py` and `Tools/validate_capture.py` to `eebb440994ea88ed58a358e3412b5c72cf4ea72fffb701186ac904dbed17bd43`. Editing or expanding an external policy file fails validation, including a whitespace-only change. Updating both source pins requires a new review.

Only 20 directed pairs involving 12 exact source triangles are listed: pool wall `DOM_01724`, faces 6–7, toward coping `DOM_01749`–`DOM_01753`, faces 6–7. Their distinct source X planes differ by 152 nanometres and round to the same uploaded float32 plane. Their signed normals must agree, and their current diagnostic receiver class must be nonfloor terminal flux. The independent full source BVH must select the claimed CPU triangle first. The same ray must intersect both exact source triangle footprints. Per-vertex rounding errors, projected plane separation and two float32 ULPs define local hit/path bounds; the hit bound also has a 2 micrometre absolute cap. Grazing rays, reverse pairs, oblique planes, foreign triangles, different normals/classes and every floor equivalence are rejected.

The existing threshold remains strictly below `0.001` for unexplained object mismatches. The original total object mismatch ratio remains visible; listed ambiguities are never described as exact IDs. A capture with listed ambiguities receives `GPU-capture-source-transport-validated-with-listed-f32-ambiguities`. Every ambiguity includes its photon index, actual CPU/GPU object and triangle indices, source geometry certificate and observed numerical error. No recorded photon bytes or energy values are rewritten.

All previous transport checks remain: finite buffers and valid sizes, exact reviewed contract, valid object/triangle ownership and named triangle footprint, reciprocal floor classification, Snell hit/path error below 2 mm, Fresnel error below `2e-5`, Beer attenuation relative error below `1e-4`, energy balance below `1e-5`, CPU floor flux error below 0.5%, integrated half-float atlas error below 0.3% and spatial atlas L1 error below 1%. Tests explicitly reject energy-preserving atlas rearrangement as well as duplicated atlas energy.

Run the CPU-only regression suite with `node --test tests/unreal-caustics.test.mjs`. It includes 24 policy cases and ten corrupt/foreign/physical transport cases, also under Python `-O`. The one-record fixture is copied from the real capture and carries its original capture and photon-buffer hashes; that fixture alone is never native validation evidence.

Revalidation must use a separate, hash-verified copy of the frozen real capture. Preserve the original strict failed receipt and original photon buffer. Invoke `python3 unreal/BreziTwin/Plugins/BreziCausticsProbe/Tools/validate_capture.py <new-copy-directory>` only on the copy. The resulting receipt validates the frozen diagnostic source transport conditions, not new GPU execution, exact triangle identity for every photon, calibrated irradiance, production caustics, visibility shadows, a finite solar disk, BRDF transport, standalone app behavior or native 4K performance.

The original failed receipt, photon buffer, atlas, contract and capture metadata remained byte-identical.
